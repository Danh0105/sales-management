# P3-7.2B — Quarantine Bootstrap trên production (runbook — CHƯA thực thi)

**Mục tiêu duy nhất:** đăng ký webhook cho OA tuyển dụng **ICHI SKILL**, lấy `RECRUITMENT_ZALO_OA_SECRET_KEY`,
rồi chuyển sang receiver **kiểm chữ ký thật**. KHÔNG bật chatbot: worker và outbound tắt suốt P3-7.2B.

Trạng thái cuối mong muốn: 3010 nhận webhook ICHI SKILL ở chế độ thường (kiểm chữ ký), event hợp lệ nằm chờ
`RECEIVED` trong inbox, 0 dòng `QUARANTINED`, OA giáo viên Kidoedu không đổi.

## 0. Nguyên tắc

- Mỗi **cổng G1…G7** dưới đây cần **duyệt riêng** trước khi chạy; xong cổng nào báo cáo rồi dừng.
- Không in / log / dán secret. Giá trị secret chỉ đi từ file 600 vào cấu hình, không qua chat, không qua dòng lệnh
  nhìn thấy được trong `ps` (dùng `env -i` + file, xem phụ lục).
- OA giáo viên (Kidoedu): không sửa `ZALO_*`, bảng `zalo_tokens`, route `/zalo/oa/webhook`. Token giáo viên TỰ
  refresh ~25 giờ/lần (đường đã vá, có khoá) nên fingerprint `zalo_tokens` đổi là bình thường. Mỗi cổng kiểm: biến
  `ZALO_*` không đổi, `/zalo/oa/webhook` không đổi, mọi lần refresh trong log là dòng "Đã refresh token Zalo OA",
  0 dòng `access_token`/`refresh_token` chưa che trong log, `getoa` giáo viên `error=0`.
- Không khẳng định Zalo sẽ gửi lại khi nhận 503/5xx/timeout: request Zalo chưa nhận được 200 **có thể mất**.
- 3011 (dev, `NODE_ENV=development`) dùng chung DB production và **công khai** (ufw ALLOW 3011 + nginx
  `api-dev.kidoedu.edu.vn` → 3011) → cờ webhook KHÔNG được đặt trong `.env` chung; chỉ đặt cho tiến trình 3010 qua env
  của pm2. Sau MỌI lần restart: kiểm `POST :3011/recruitment/channels/zalo/webhook` → 404 và env pm2 của `sales-be`
  không có `RECRUITMENT_ZALO_ENABLED=true` (xem mục 6).
- Đã kiểm (09–12/10): `pm2 restart <app> --update-env` **gộp** biến mới vào env sẵn có (kể cả khi chạy từ
  `env -i`), giữ qua các lần restart sau; muốn tắt phải đặt rõ `=false`.

## 2. Các cổng

### G1 — Mã phát hành (quyết định của user)
Chọn một: (a) fast-forward `master` → SHA release, rà bí mật toàn bộ commit mới (repo GitHub **công khai**,
không CI/CD), push thường (không force); hoặc (b) deploy từ `release/phase3`, đưa vào `master` sau. Khuyến nghị
(a) để production luôn chạy commit nằm trên `master` (hotfix sau này không làm mất Phase 3).

### G2 — Preflight + sao lưu (không đổi production)
1. Worktree sạch đúng SHA; `npm ci`; `npm run build`; `diff -rq` với `dist/` live: chỉ khác phần Phase 2/3 +
   quarantine, không mất file, không đụng `zalo-token|notify-zalo|zalo-oa|fcm|database`.
2. `pg_dump -Fc sales_db` đầy đủ → `/root/backups/sales_db-before-p372b-<ts>.dump` (600; ~129 MB); kiểm
   `pg_restore --list` đọc được. Tar `dist/` hiện tại (600).
3. Ghi lại: pm2 trạng thái + số lần restart 3010/3011; tên biến env pm2 (không giá trị); fingerprint `zalo_tokens`;
   `SELECT count(*)` các bảng `recruitment_*` (đang 0 ứng viên / hội thoại / tin); dung lượng đĩa.
4. Kiểm `recruitment_*` mới chưa tồn tại (bảng `migrations` chỉ 2 dòng Init + MapExpenseRequestSchoolYear).

### G3 + G4 — Migration + deploy ứng dụng, mọi công tắc TẮT (cửa sổ bảo trì ~15 phút, giờ thấp điểm)
1. Chạy LẦN LƯỢT 8 migration bằng `sales_migrator`, mỗi cái một transaction (`run-migration.js`), dừng ngay khi
   có lỗi. Sau đó schema-diff (kết nối bằng `sales_app`) = 0. Code cũ (`cf7b51c`) vẫn chạy được với lược đồ mới
   (bảng/cột mới nullable/có default) — riêng CHECK `zalo_oa_id` của `recruitment_candidates` sẽ chặn code cũ tạo
   ứng viên có `zalo_user_id` (API AI production đang tắt, bảng rỗng) → làm G4 ngay sau G3.
2. Thêm vào `.env` chung (giá trị từ `/root/recruitment-oa.env` + `/root/recruitment-oa.keys.env`, không in):
   `RECRUITMENT_ZALO_APP_ID`, `RECRUITMENT_ZALO_OA_ID`, `RECRUITMENT_ZALO_APP_SECRET`, `RECRUITMENT_ZALO_TOKEN_KEY`,
   `RECRUITMENT_CHANNEL_API_KEY`. KHÔNG thêm `RECRUITMENT_ZALO_ENABLED` / `_WEBHOOK_QUARANTINE` / `_OA_SECRET_KEY`.
   `RECRUITMENT_WORKER_ENABLED` và `RECRUITMENT_ZALO_OUTBOUND_ENABLED` không đặt (= tắt).
3. `rsync -a --delete <release>/dist/ dist/` → restart 3011 (không `--update-env`) → health (login 401, log 0 lỗi
   mới) → restart 3010 → health. 3011 lỗi → dừng, không đụng 3010 (như Gate 1).
4. Nạp credential đã mã hoá `/root/recruitment-oa.credential.json` vào `recruitment_zalo_credentials` (đúng cột,
   giữ nguyên bản mã — cùng `RECRUITMENT_ZALO_TOKEN_KEY` đã dùng để mã hoá); kiểm giải mã trong bộ nhớ khớp
   fingerprint. Không refresh.
5. Kiểm: route webhook trên 3010 và 3011 → 404 (cờ tắt); fingerprint `zalo_tokens` không đổi.

### G5 — Mở cửa sổ cách ly trên 3010 (mục tiêu ≤ 24 giờ, tối đa 72 giờ)
1. `env -i … RECRUITMENT_ZALO_ENABLED=true RECRUITMENT_ZALO_WEBHOOK_QUARANTINE=true pm2 restart sales-management
   --update-env` → `pm2 save`. App từ chối khởi động nếu đã có OA secret key hoặc thiếu khoá mã hoá.
2. Kiểm không ghi dữ liệu: `POST` khai sai `app_id` tới `https://sales.kidoedu.vn/recruitment/channels/zalo/webhook`
   → **403** `APP_MISMATCH` (chế độ thường sẽ là 401) ⇒ đang ở chế độ cách ly; 3011 → 404.
3. User đăng ký URL trên Zalo Developers (app ICHI SKILL → Webhook). Theo dõi: request `ZaloWebhook` trong log
   nginx, `GET /recruitment/operations/webhook-quarantine` (đăng nhập `nhansu`) có thêm dòng `QUARANTINED`.
4. User lấy OA Secret Key → `/root/recruitment-oa.env` (600), KHÔNG dán vào chat.
5. Một tài khoản Zalo NỘI BỘ nhắn OA ICHI SKILL đúng 1 tin thử (để có ít nhất một request thật có chữ ký trong
   cách ly — request thử khi đăng ký URL có thể không ký).

### G6 — Chuyển sang receiver kiểm chữ ký, KHÔNG khoảng trống
0. **Preflight chữ ký thật (bắt buộc, chỉ đọc):** `node integrations/openclaw/scripts/zalo-quarantine-preflight.js
   --dist <release>/dist --env-file /var/www/sales-management/.env --env-file /root/recruitment-oa.env` — giải mã các
   dòng `QUARANTINED` trong bộ nhớ, chạy đúng hàm parse + kiểm chữ ký của bản phát hành với OA secret key, chỉ in số
   lượng, transaction READ ONLY. Thoát 0 (≥ 1 request khớp, gồm tin thử nội bộ, không dòng hỏng) → được làm tiếp.
   Thoát 2 (0 khớp) → DỪNG, không cutover: công thức/khoá sai hoặc chưa có request thật có chữ ký — giữ cách ly, báo.
   (Đã thử trên staging: khoá đúng → 1 khớp / 2 không khớp, thoát 0; khoá sai → 0 khớp, thoát 2; dòng vẫn
   QUARANTINED, inbox không đổi.)

Lý do cần 2 tiến trình: chuyển chế độ phải restart 3010 (~5 giây); trong lúc đó request Zalo bị lỗi và có thể
mất. Cách không khoảng trống:
1. Đưa `RECRUITMENT_ZALO_OA_SECRET_KEY` vào `.env` chung (3011 vẫn tắt cờ nên không dùng tới).
2. Bật tiến trình tạm `sales-recruit-cutover` (cùng `dist/`, `PORT=3017` — cổng trống, ufw không mở;
   `NODE_ENV=development` để không chạy cron; `RECRUITMENT_ZALO_ENABLED=true`, quarantine tắt). Health.
3. nginx: thêm `location = /recruitment/channels/zalo/webhook { proxy_pass http://127.0.0.1:3017; … }` trong
   server `sales.kidoedu.vn` → `nginx -t` → `systemctl reload nginx` (reload êm, không cắt kết nối đang chạy).
   Kiểm request không chữ ký qua domain → **401** (đã ở receiver kiểm chữ ký).
4. Restart 3010 với `RECRUITMENT_ZALO_WEBHOOK_QUARANTINE=false` (cờ ENABLED giữ true) → `pm2 save` → health;
   kiểm trực tiếp 3010 request không chữ ký → 401.
5. Gỡ khối `location` → `nginx -t` → reload → webhook về lại 3010. `pm2 delete sales-recruit-cutover`.
6. `POST /recruitment/operations/webhook-quarantine/verify` (nhansu): mọi dòng `QUARANTINED` đã COMMIT được xác
   minh lại bằng chữ ký thật — khớp mới vào inbox (chống trùng), không khớp → `REJECTED`. **Đây là bước duy nhất
   promote dữ liệu cách ly.** `failed`/`undecryptable` > 0 → dừng, báo.
7. Kiểm công thức chữ ký bằng traffic thật: một tài khoản Zalo nội bộ nhắn OA ICHI SKILL một tin thử → 200,
   event `RECEIVED` (worker tắt nên nằm chờ). Nhận 401 → dừng, báo — KHÔNG nới fail-closed.
Phương án dự phòng (đơn giản hơn, có khoảng trống ~5 giây — chỉ dùng nếu user chấp nhận): bỏ bước 2–3–5,
restart thẳng 3010.

### G7 — Đóng cửa sổ
`GET …/webhook-quarantine`: 0 `QUARANTINED`; `RECRUITMENT_ZALO_WEBHOOK_QUARANTINE=false` trong env 3010;
fingerprint `zalo_tokens` không đổi; báo cáo. Ghi chú: khi worker còn tắt, nội dung tin `RECEIVED` nằm trong inbox
(bộ dọn 7 ngày chạy trong worker) — bắt đầu P3-7.3 hoặc dọn tay trong vòng 7 ngày.

## Phụ lục — mẫu lệnh (không in secret)

```bash

  pm2 restart sales-management --update-env && pm2 save

# Migration (mỗi file một lần, dừng khi lỗi); mật khẩu đọc từ file 600 vào env của chính lệnh:

DB_HOST=127.0.0.1 DB_PORT=5432 DB_NAME=sales_db DB_USER=sales_migrator DB_PASSWORD="$SALES_MIGRATOR_PASSWORD" \
  node - <release>/dist/migrations/<file>.js up < integrations/openclaw/staging/run-migration.js
```
